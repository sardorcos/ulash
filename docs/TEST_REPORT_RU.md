# Отчёт о проверке технической альфы 0.1.0

Дата: **20 ноября 2026 года**. Среда общей логики: Linux, Flutter **3.50.1**, Dart **3.14.0**. Проверка на физических iPhone, Android и Windows в этом отчёте не заявляется.

## Автоматические проверки

| Набор | Число | Результат и содержание |
|---|---:|---|
| Storage | 20 | SQLite и реальные файлы: consent, immutable source, provider stream, size/offset/incarnation, обрыв, хвост после crash, missing-prefix, SHA mismatch, пустой файл, commit-intent recovery, pause ownership, отмена, safe names, symlinks, store lease |

`dart analyze --fatal-infos` для ядра и `flutter analyze` для приложения завершены без замечаний. Зависимости разрешаются с `--enforce-lockfile`. Скрипт `scripts/verify.py` выполняет эту последовательность.

В обычном прогоне дополнительно виден **1 skip**: `capture_previews_test.dart` намеренно отключён без `CAPTURE_UI=true`. Это инструмент создания screenshots, а не пропущенный тест передачи. Он отдельно запускался для создания имеющихся previews.

Полный текст конечного прогона сохранён в `verification/automated_tests.log`; итоговые показатели — в `verification/summary.json`.

| Поле | Фактический результат |

| Первое доверие | Генерация временных EC-идентичностей; ручное approval; commit pairing |

SHA-256 обоих файлов:

```text
64ac271682815a3defa1ddb2320b525ff25d5102f901be28b960200f66d3c407
```

Машиночитаемый исходный результат и независимая проверка: `verification/loopback_1g.json`. Файлы общей длиной более 2 ГиБ не включены в архив исходников; их можно воспроизвести командой из README.

**69,255 с не является измерением скорости на телефонах.** Это время всего синтетического, но реально выполняемого файлового сценария в одной среде. Отдельные два процесса, принудительное выключение питания, маршрутизатор без WAN и Wi-Fi между устройствами в данном тесте не использовались. Возможность восстановления здесь доказана повторным открытием Host/SQLite/файлового состояния, а не исчерпывающей кампанией аппаратных сбоев.

## Интерфейс

Снимки `docs/previews/` получены рендером настоящих Flutter widgets с bundled fonts. В списках нет придуманных получателей, файлов или истории. Для изображения приглашения использовался временный настоящий loopback Host; после снимка он закрыт, секреты уничтожены. Изображённый QR уже не даёт доступа к активному приложению.

Ширина 360 px и text scale 180% проверены widget-тестами. Снимки мобильного размера не означают, что приложение запускалось на iPhone или конкретной модели Android.

## Нативные сборки

Финальная debug-сборка **ARM64** получена: **119 608 218 байт**, min SDK **29**, target SDK **37**, ABI **arm64-v8a**, подпись Android Debug v2 проверена `apksigner` (exit 0), ZIP CRC корректен. Сборка выполнена после последних изменений Dart-исходников. APK на физическое устройство здесь не устанавливался. Подробные данные содержатся в `verification/android_arm64_debug.json`: размер, SHA-256, package name, min/target SDK, ABI и результат проверки подписи.

Windows и iOS представлены исходными платформенными проектами. В данной Linux-среде их нативные сборки и установка на устройства не выполнялись. Production signing, App Store/Google Play/Microsoft Store публикация и установка получателями не выполнялись.

## Что ещё не доказано

- Все шесть межплатформенных направлений и ещё три направления внутри одной ОС.
- Работа реальной локальной сети при отключённом WAN, hotspot/гостевые сети, firewall и VPN.
- Реальные Keychain/Android secure store/Windows DPAPI persistence и системные permission dialogs на целевых устройствах.
- Работа камеры, native file providers, системного просмотрщика и экспорта файлов.
- Файлы 5/10 ГиБ, 1 000 файлов, 50 ГиБ пакет, RAM budget и p95 discovery/start.
- iOS Share Extension/native background, Android foreground service, Windows tray.
- Долговременное хранение, квоты и автоматическая очистка.
- Защита от конкурентного локального filesystem actor, аппаратная порча и отключение питания.

Следующий необходимый gate — установка фактических сборок и аппаратная матрица из раздела 24 ТЗ. Автоматические проверки помогают подготовить этот этап, но не закрывают его автоматически.
