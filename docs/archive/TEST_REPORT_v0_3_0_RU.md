## 2. Фактическая автоматическая докачка

Два настоящих `TransferAppController` обмениваются данными по TCP/TLS с закреплённым SPKI. Между ними находится непрозрачный TCP relay: он пересылает зашифрованные байты и один раз разрывает сокеты после появления подтверждённого префикса. Он не создаёт HTTP-ответов и не подменяет согласие или receipt. Исходный файл удаляется после подготовки, поэтому отправка использует сохранённую копию.

| Показатель заключительного прогона | Результат |
|---|---:|
| Полный файл | **16 777 353 байт** |
| Durable offset при повторе | **7 782 394 байт** |
| Принудительных обрывов | **1** |
| Автоматических повторов | **1** |
| Предписанная задержка | **1000 мс** |
| Зашифрованных байтов Source → Sink после обрыва | **9 051 910 байт** |
| Полное время сценария | **5546 мс** |
| Идентификаторы запроса и передачи | Сохранены |
| Ручное Source resume | Не вызывалось |
| Полный SHA-256 результата | Совпал с исходным содержимым |

```text
e359e4f20be97fccaf872546d5029086560fa3d7d238889ca468ffbef0f12e68
```

Wire-счётчик включает TLS и служебный трафик; он не равен чистому payload. Проверка подтверждает, что после разрыва не был заново передан весь файл. Устойчивое смещение зависит от конкретного расписания потоков, поэтому между прогонами может различаться.

Ожидание backoff в тесте управляется тестовым планировщиком. В production используется обычный отменяемый таймер. **5,546 секунды не являются измерением скорости Wi-Fi или фактической задержки повтора на телефоне.** Проверка SHA-256 выполнена Dart `crypto` по реально сохранённому файлу и сравнена с hash исходного детерминированного содержимого; независимый Python verifier здесь не использовался.

Машиночитаемые данные: `verification/network_retry_v03.json`; они связаны SHA-256 с заключительным логом. Старый сценарий **1 ГиБ** относится к 0.2 и в этой итерации повторно не выполнялся. Его исходное доказательство сохранено в `verification/loopback_v02_1g.json`, а предыдущий отчёт — `archive/TEST_REPORT_v0_2_0_RU.md`.

## 3. Восстановление и сроки

Проверены граница 119/120 секунд, терминальное истечение без согласия, повтор того же requestId, уведомление без опроса, освобождение всех ожидающих слотов, отказ от записи до согласия и истечение во время медленной подготовки места. Восстановление старой SQLite-схемы сохраняет принятую передачу, paused prefix, incarnation, флаг Sink pause и готовый файл.

Во время процесса срок определяется монотонным отсчётом. После закрытия и запуска используется сохранённый UTC deadline с ограничением оставшегося времени; откат раньше исходного создания приводит к истечению. Это не позволяет обнаружить каждое изменение системных часов между запусками и не даёт независимого доказательства реальных 120 секунд при таком изменении.

Новый enum `expired` требует клиента 0.3 для правильного отображения. Клиент 0.2 прекращает обработку неизвестного состояния и не объявляет доставку. Полная mixed-version матрица не выполнялась.

## 4. Очистка и защита последней копии

В новых регрессионных проверках есть смешанный пакет: один файл готов, второй содержит только устойчивый префикс. Подтверждённая очистка удаляет только незавершённую часть, обнуляет offset и освобождает резерв; готовый файл снова читается и проверяется. Неперечисленная передача сохраняется. Повтор очистки не удаляет ничего дополнительно.

Отдельно проверены активный writer, терминально ошибочный partial, отсутствие файла после прерванного удаления, подмена родительского каталога символической ссылкой и позднее подтверждение после завершения commit. Если запись находится в неразрешённом `committing`, удаление запрещено до recovery, чтобы не потерять проверенный кандидат окончательного результата.

Автоматическая исходящая очистка ограничена полным проверенным `completed` receipt. Тест удаления оригинала → отказ получателя → новая отправка доказывает сохранность единственной подготовленной копии и возможность использовать её по новому явно подтверждённому запросу. Пакет с committed-файлами не предлагается повторять целиком.

## 6. Изображения интерфейса

Изображения в `docs/previews/` создаёт настоящий Flutter UI с реальным контроллером, временными SQLite и TLS Host. Контент не заполняется вымышленными пользователями, скоростью или передачами. Пустое хранилище и недоступность нативного измерения в Linux отображаются честно. Мобильный размер — рендер адаптивного интерфейса, а не снимок установленного Android/iOS приложения.

Время жизни тестового Host ограничено harness; после него временные секреты и данные удаляются. В harness согласовано завершение задач между тестовыми и реальными часами: после рендера подтверждено завершение настоящего контроллера. Это изменение тестовой обвязки не меняло production-код собранного APK. QR-приглашения в изображения не сохраняются. Harness не является pixel regression suite.

## 7. Краткая приёмка на физических устройствах

| Шаг | Ожидаемый проверяемый результат |
|---|---|
| Установить 0.3 поверх выданной 0.2 | Версия обновилась, прежние пары/история/файлы сохранились |
| Запустить 0.3 на обоих Android | LAN permission и камера корректно разрешаются/отклоняются |
| Подключить по QR и отправить небольшой файл | Нет file bytes до явного согласия, результат совпадает по SHA-256 |
| Не отвечать на предложение 120 с | Появляется истечение; старый запрос не восстанавливается |
| Нажать «Отправить снова» | Новый запрос, новое согласие, прежний результат остаётся в истории |
| Кратко разорвать сеть при большом файле | Видны ограниченные повторы и докачка подтверждённого префикса |
| Поставить паузу во время backoff | Повтор прекращается и сам не возвращается |
| Очистить незавершённый смешанный пакет | Partial удалён; готовый файл читается; новый пакет вне списка сохранён |
| Проверить системный экспорт | Сохранённая копия читается выбранным provider; отмена не меняет сетевой результат |

Эта таблица является планом приёмки, а не отметкой о выполнении. Общая физическая матрица из `DEVICE_TEST_MATRIX.md`, отсутствие WAN, все шесть межплатформенных направлений и три направления внутри одной ОС остаются открытыми.

## 8. Не проверено / не реализовано

Нативные iOS и Windows builds, аппаратное обновление Android, системные providers и camera, реальная сеть и смена интерфейса, power-loss campaign и независимый аудит не выполнялись в этой Linux-среде. Не заявляются throughput, p95, RAM или работа максимальных 10 ГиБ/1000 файлов/50 ГиБ пакета на устройстве.

Автоматические сроки 7/30 дней, лимит истории, orphan sweep, выборочный retry failed file, pull/reset-receive и фоновые платформенные службы в эту итерацию не входят. **Gate A не закрыт.**
