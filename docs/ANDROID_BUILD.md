# Android debug APK

This alpha uses the Android project generated by Flutter 3.50.1. The current
project targets API 37 with minimum API 29; check `android/app/build.gradle.kts`
for authoritative values. Use a full Java 21 JDK (including `javac`) and the SDK/NDK versions requested by
the checked-in Gradle files. Android SDK licenses must already be accepted by
the developer building the project.

## Standard developer machine

From `apps/file_transfer`:

```sh
flutter pub get
flutter build apk --debug
```

The generated debug artifact is normally at:

```text
apps/file_transfer/build/app/outputs/flutter-apk/app-debug.apk
```

The debug key is a development key. A successful build does not establish
physical-device correctness, store approval or a production signing identity.

For a smaller APK intended for a 64-bit ARM Android device:

```sh
flutter build apk --debug --target-platform android-arm64 --split-per-abi
```

Use `build/app/outputs/flutter-apk/app-arm64-v8a-debug.apk` for that build.
`--split-per-abi` filters native libraries contributed by plugins as well as
the Flutter engine; inspect the final APK's ABI metadata before distribution.

## Managed environment using an inherited HTTP proxy

Some Java/Gradle versions do not use `HTTP_PROXY`/`HTTPS_PROXY` automatically.
Use the helper from the repository root:

```sh
python3 scripts/build_android.py \
  --flutter /absolute/path/to/flutter/bin/flutter \
  --android-sdk /absolute/path/to/android-sdk \
  --java-home /absolute/path/to/jdk-21 \
  --gradle-user-home /absolute/path/to/gradle-cache \
  --no-pub \
  --log /absolute/path/to/android-build.log
```

Omit `--no-pub` when dependencies have not yet been resolved. The helper reads
the active inherited proxy endpoints at invocation time, supplies matching JVM
properties for this process, and avoids reuse of a daemon with stale proxy
settings. It preserves the inherited proxy variables and TLS trust settings.
It does not save machine proxy addresses or credentials in project files.

`--java-home` is optional when `JAVA_HOME` already points to a complete JDK.
Check `"$JAVA_HOME/bin/javac" -version` before building: a runtime-only Java
installation can run Gradle yet fail when an Android plugin needs compilation.
Pass `--target-platform android-arm64 --split-per-abi` to the helper for the
64-bit ARM package described above.

The helper deliberately refuses to put proxy passwords into JVM arguments.
For authenticated or non-HTTP proxy configurations, use the environment's
approved Java credential/proxy setup.

Do not disable TLS verification, change repository hosts to unverified mirrors,
or weaken policy rules to complete a build. If a registry denies access,
identify the host/status and arrange the required access through the normal
environment configuration.

## Gradle distribution integrity

`gradle-wrapper.properties` pins the official Gradle 9.5.0 all-distribution
SHA-256. The checksum was verified against the published checksum at:

https://services.gradle.org/distributions/gradle-9.5.0-all.zip.sha256

Keep the distribution URL and checksum together when deliberately updating
Gradle. SDK caches, Gradle caches, machine `local.properties`, build logs and
signing secrets are not source deliverables.

## Required physical checks after installing

1. First-launch file picker and local-network permission flow.
2. Pair with another installed client using the invitation, then confirm the
   expected peer on the receiver.
3. Transfer a known file in both directions and verify its content.
4. Disable the router's WAN access while preserving LAN and repeat.
5. Interrupt Wi-Fi, restore it, and verify resume from the sink's durable offset.
6. Verify cancellation and handling of denied permissions.
7. Keep the alpha app in the foreground: native background service behaviour
   is not a completed capability of this build.
